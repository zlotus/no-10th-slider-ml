5. 师夷长技以制夷：要借助模型创造出什么样的能力才能卷过模型 / 竞品？​
   a. 尽量落在模型难以彻底包圆的领域​
   b. 和竞品存在差异化 / 明显优于竞品​
   c. 并且要能真正解决用户实际存在的核心痛点​
6. 关于存量功能与模型能力的结合​
   a. 不要硬上大模型：​
       i. 产品决策上：是否真正带来增量；是否真正解决问题；是否符合用户习惯；是否适合做成对
            话式入口……​
       ii. 技术决策上：LLM / VLM 最大的工程弊端在于耗时和不确定性。​
   b. 什么时候上大模型：​
       i. 只有大模型才能做的场景：开放语义、模糊意图理解、跨模态推理、生文生图等等。​
       ii. 耗时相对不敏感，起码接受秒级别延迟（对于耗时敏感场景，模型也可以作为决策节点介
            入）​
       iii. 上之前控制好耗时 / 稳定性问题（耗时优化：压缩输入图、减少输出长度、采用轻量模型
            等）​
       iv. 模型增益不一定要体现在 C 端产品上，也可以体现在产品背后​
7. For Agent 开发：技术层面具体要做好什么​
   ◦ 把效果做好：对齐业内最先进的 agent 工程化实现（学最好的，不要自己从 0 摸索试错） + 技
      术精细化与技术创新（并非所有通用最佳实践都适合于具体的业务场景）​
   ◦ 把链路做稳：管好 bug、稳定性、耗时（非常基础，不一定能决定成功但搞不好能决定失败）​
   ◦ 支持快速迭代：积极探索 AI 提效、闭环验证；探索产研协同迭代模式；做好基建（模型两个月
      一发版、AI 跑 demo 如火如荼的时代下，更需要快速验证试错，而技术在这个环节起到更关键
      的作用）​
   ◦ 提供技术视角输入 + 补齐自身视野和技能短板：技术相对不了解产品，产品相对不了解技术，
      但是 AI 时代的许多决策都很需要同时了解产品 + 技术，所以可以主动提供这一块的输入，同时
      主动沉淀自身的产品思维；另外即使是在技术领域内部，未来想要闭环验证一件事情，也可能
      会需要一些算法认知 + 跨端工程实践能力，所以可以主动补齐自己的视野 / 技能短板。
